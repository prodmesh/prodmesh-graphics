# Spec — Control server HTTP API and SSE topics

**Normative.** The control server's surface, on port **8519**. This is also the
public integration API ([ADR 0014](../decisions/0014-control-surfaces-and-where-they-terminate.md)):
every control surface is an adapter over it, and a third party writing against
this document gets exactly what the Show view gets.

Related: [ADR 0008](../decisions/0008-snapshots-stream-cues-are-acked.md) for the
snapshot/event split, [ADR 0013](../decisions/0013-stations-users-and-acls.md)
for auth.

## 1. Conventions

- JSON in and out. Routers declare full `/api/...` paths.
- **Auth**: `x-prodmesh-station` header identifies the station (no permissions);
  `Authorization: Bearer <token>` identifies the user. **401 means nobody is
  logged in; 403 means this operator lacks the permission** — the browser's only
  way to tell those apart. Refusals carry a human `label`:
  ```json
  { "error": "permission_required", "permission": "graphics.operate",
    "label": "Take graphics on air" }
  ```
- **Broadcast aliases are accepted and documented** ([ADR 0015](../decisions/0015-four-modes-and-plain-words.md)):
  `take_id` is a stable external identifier on an Item, and `Scene` is a
  documented synonym for Template. The UI never shows these; integrators get the
  words their other equipment uses.
- **Layers are addressed by name, never by index.**

## 2. Cues — the operative endpoint

```http
POST /api/cue
{
  "cue_id": "01JA…",          // REQUIRED — generated by the caller, §2.1
  "node": "booth-1",
  "output": "out-0",
  "layer": "Lower Third",
  "op": "take",                // take | take_out | update | clear_layer
                               // | clear_all | arm | preload | timeline
  "item": "01JB…",
  "data": null,                // for `update`
  "deadline_ms": 500
}
```

| Response | Meaning |
|---|---|
| `200 { result: "applied", fired_at_frame, at_utc, seq }` | On air |
| `200 { result: "deduped", … }` | Same `cue_id` already applied |
| `200 { result: "superseded", seq, label }` | A newer take to the same layers replaced it before it fired (ADR 0017). The system working, not refusing — distinct from a late rejection |
| `409 { result: "rejected", reason }` | `not_ready`, `no_such_layer`, `unreadable_template` |
| **`503 { error: "cue_not_acked" }`** | **The node did not confirm within the deadline** |

> **This endpoint is synchronous.** It does not return until the node acks or the
> deadline expires. A fire-and-forget button on a broadcast system is worse than
> no button, because it teaches an operator to trust something untrue. The Show
> view renders `503` as words: *"Booth-1 didn't confirm the take. Check the layer
> before taking again."*

### 2.1 `cue_id` is the caller's responsibility

Generate it **where the human acted** — at button-press, at key-down, at the GPI
edge — and reuse it on retry. It is carried unchanged to the node, which dedupes
on `(epoch, cue_id)`. A client that generates a fresh id per retry has defeated
the mechanism.

`POST /api/cue/batch` takes an array and applies them in order, atomically per
node. Used for multi-layer looks.

### 2.2 The cue socket — `GET /api/cue/socket` (WebSocket)

Follow mode's path (ADR 0017). It takes on every keypress, and an un-acked POST
holds one of the six HTTP/1.1 connections a browser allows per origin — so a
burst queued behind its own first keypress. The socket carries any number of
cues in flight. **It carries cues and their acks and nothing else**; snapshots
stay on SSE (ADR 0008).

JSON text frames:

```
→ { "type": "hello", "station": "<station token>", "bearer": "<session token>" }
→ { "type": "cue", …the POST /api/cue body… }          any number, unawaited
← { "type": "ack", "cue_id": "01JA…", "http": 200, …the POST /api/cue body… }
```

- `hello` carries what headers would, because a browser socket cannot send
  them. It may be repeated when identity changes; each cue is checked against
  the latest one, **per cue** — signing out stops the next keypress, not the
  next reconnect.
- Every cue goes through the same dispatch and the same permission check as
  `POST /api/cue`, and its ack carries the status and body that endpoint would
  have returned. `surface` defaults to `show_view`.
- Cues reach the node in the order they arrived on the socket. Acks return in
  the order nodes answer, matched by `cue_id`.
- The socket is an optimisation, never a dependency. A client re-sends anything
  the socket could not deliver by `POST /api/cue` **with the same `cue_id`** —
  safe because the node dedupes on it (§2.1).

`POST /api/templates/:id/publish` takes the compiled SceneDoc and its manifest.
**The server validates the manifest against a JSON schema and stores the SceneDoc
as an opaque blob** — it never parses the scene format
([ADR 0004](../decisions/0004-one-repo-crates-and-packages.md)).

Item writes are validated against the pinned revision's `fields` from the
manifest: `required` present, `max_len` respected, referenced assets resolvable.

## 4. The topic stream

```http
GET /api/stream?topics=node:booth-1:health,output:out-0:layers
event: msg
data: {"topic":"output:out-0:layers","data":{…}}
```

One `EventSource` per browser tab, multiplexed by named topic — ProdMesh-Control's
`streamHub` model, unchanged. Refcounted producers (nobody polls a node no
browser is watching), `valid()` rejects topics naming nothing real (subscribing
*starts work*, so accepting any string is a resource-exhaustion primitive),
`snapshot()` paints a joiner immediately, `MAX_TOPICS = 64` per connection,
20 s heartbeat.

**Under backpressure the hub keeps at most one pending frame per topic, newest
wins.** That is correct only for snapshots.

### 4.1 Topic catalogue — snapshots only

| Topic | Payload |
|---|---|
| `node:<id>:health` | reachable, version, uptime, assignment gen |
| `node:<id>:telemetry` | fps, dropped, late, gpu_ms, cpu, temp, disk |
| `node:<id>:sync` | genlock present, locked, ref format |
| `node:<id>:staging` | bytes done/total, pending count, current file |
| `output:<id>:layers` | each layer's occupant, phase, timeline, t_ms |
| `item:<id>:readiness` | ready \| blocked + missing hashes |
| `rundown:<id>:cursor` | current playlist and item |
| `preview:<id>:stats` | fps, bitrate, dropped |

### 4.2 The one event feed, and the rule behind it

`show:<id>:cuelog` publishes **`{ head_seq, entries[] }`** — a sliding window of
the last N take-log entries, not one entry per event.

> **An event stream reaches the browser as the snapshot of a log tail.**
> Conflation is safe again because the newest frame *contains* everything the
> dropped frames carried.
>
> **Never publish a bare `{event:"take", …}` frame on a conflating topic.**

Gap recovery is over plain HTTP:

```http
GET /api/cuelog?since=8801&limit=500
→ { "head_seq": 8813, "entries": [ … ] }
```

A log entry records what happened *and which surface did it* — otherwise the log
is confusing the first time someone uses a GPI:

```jsonc
{ "seq": 8813, "cue_id": "01JA…", "at_utc": 1786487930986,
  "fired_at_frame": 1841944, "node": "booth-1", "output": "out-0",
  "layer": "Lower Third", "op": "take", "item": "01JB…",
  "item_label": "Pastor Dan Whitfield",
  "surface": "show_view" | "companion" | "rosstalk" | "gpi" | "osc"
           | "midi" | "api" | "node_local",
  "user": "jbeale" | null, "station": "booth-mac" | null,
  "result": "applied" }
```

## 5. Auth

| Method | Path | Notes |
|---|---|---|
| `POST` | `/api/stations/register` | Returns a station token. **Grants no permissions.** |
| `POST` | `/api/auth/login` | Username + PIN → bearer token, 8 h TTL. Throttled per station+username. |
| `POST` | `/api/auth/logout` | |
| `GET` | `/api/auth/me` | Permissions the UI uses to hide controls it would be refused |
| `GET/POST` | `/api/users` · `/api/groups` · `/api/stations` | `graphics.users.manage` / `graphics.stations.manage` |

**A station marked *trusted for operation*** may send `graphics.operate` cues
within its configured output/layer scope with no user logged in
([ADR 0013](../decisions/0013-stations-users-and-acls.md) §"the one change"). The
audit log records the station acting with no user, which is the honest record.

**Hiding controls in the UI is guidance. The server is the boundary.**

## 6. Errors

```json
{ "error": "<machine_code>", "label": "<human sentence>", "detail": { } }
```

`label` is what the UI shows, and it follows `docs/UI_TEXT.md`: name the thing,
not the failure. "Booth-1 is offline. Anything already on air is still on air."
beats "Connection error."

| Code | HTTP |
|---|---|
| `permission_required` | 401 / 403 |
| `cue_not_acked` | 503 |
| `not_ready` | 409 |
| `node_offline` | 503 |
| `unreadable_template` | 409 |
| `validation_failed` | 422 |

## 7. Versioning

The API is versioned by the server's `X-PMG-Api` response header and an
`/api/version` endpoint reporting `{ api, server, proto_ver, scene_reader_major }`.

Additive changes do not bump. A breaking change ships behind `/api/v2/…` with the
previous surface maintained for one minor release — because Companion modules,
DashBoard panels, and a customer's own scripts are all clients, and none of them
upgrades on our schedule.
